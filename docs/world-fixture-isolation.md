# Nonshipping world fixture module boundary

## Purpose and authority

This repository owns the source profiles and their packaging. Forge's actual named module and
loaded owning descriptor establish the runtime module result; source layout and pure controls do
not establish native acceptance. Shared authorization and retention rules remain in the
[workspace documentation](../../../better-content-modpack/docs/README.md).

## Original codec dispatch proof

The fixture observes the original serializer-registry decode returns and original root parse
extraction, not a second call to a loaded modifier's `codec()`. In pinned Goety 8087429,
`AddItemLootModifier.CODEC` is an unmemoized supplier of newly built codecs (unlike its memoized
InstantPick codec); comparing a fresh instance to the registered codec is not native provenance.
Bounded scalar witnesses require the exact original registered codec object/reverse key, successful
original root return, canonical input digest, implementation class, complete count and row order.
The pinned native loader-byte witness still establishes its builder-to-loaded-list traversal.
No codec is memoized/replaced and no parse is repeated. Metadata failures invalidate proof without
catching the original extraction call or changing its result/error consumer/Throwable. Helpers are
outside all reserved Mixin prefixes, and every new helper/observer is forbidden in shipping archives.
Source/SDK/AP controls do not establish actual transformed execution or World/Geology acceptance.

### Supported registration and template filtering

The table's namespace labels identify the two **logical profiles**, not independent engine filters.
Pinned Forge `ForgeGameTestHooks` posts `RegisterGameTestsEvent` and then automatically adds every
`@GameTestHolder` class. `GameTestRegistry` filters methods by their explicit template namespace,
which overrides a holder's fallback value. Therefore the two world classes deliberately have no
auto-holder annotations: only the original selected subscriber registers its one class. Both engines
filter `better_cave_encounters_world_tests`, the original explicit template namespace. The geology
profile remains independently selected by `bc.geologyQualification`, not by a false geology template
filter. Missing/extra/duplicate cases and wrong engine filters fail the narrow source controls.

## Existing API contract mappings

These repairs adapt stale references that could not compile against the owning APIs; there is
no historical working execution of those stale calls to claim byte-for-byte runtime equivalence.
The evidence is the actual receiving contract and preserved surrounding fixture behavior, not
merely successful compilation.

- **`Track.cooldownUntil(now + 20_000)` → `Track.recoveryUntil(now + 20_000)`.**
  `DirectorSavedData.Track` stores that exact long in `recoveryUntil`, persists it as
  `RecoveryUntil`, and exposes the same value through `recoveryUntil()`. `DirectorRuntime`
  supplies `now < track.recoveryUntil()` to its pacing policy and itself writes recovery
  deadlines through this setter. The fixture's existing intent is to suppress scheduled waves
  while isolating mechanics; the original full-cadence world case remains unchanged. The
  player, tick, 20,000-tick offset, invocation point and repeated setup are unchanged.
- **`SpawnLocator.diagnose(...)` → existing `DepthDirectorDiagnostics.diagnose(...)`.**
  The existing public diagnostic surface creates a diagnostic Mob, calls the actual
  `inspectCandidate`, Forge position, collision and border checks, then discards it in `finally`.
  This remains the same argument expression in the original native-admission assertion message,
  after the actual spawn attempt. `result.spawned()`, the spawn query/RNG, retries and subsequent
  checks are unchanged. No new probe is invoked by production playtest logging. Java eagerly
  evaluates this existing message expression even on assertion success; this repair does not
  introduce lazy evaluation or conceal that fixture behavior.
- **Offspring `Entity` parent → guarded `Mob` before `isDirectorMob(Mob)`.**
  The bound Compat event's parent contract is `Entity`, while `SpawnLocator.isDirectorMob`
  accepts `Mob`. The same `instanceof Mob parent` guard is already used by production
  `DirectorLineages`. A non-Mob cannot satisfy the director-Mob predicate. The original
  `currentId` filter, completion callback, inserted-only counting and child UUID bookkeeping
  remain unchanged. No event is force-allowed or admitted on a different predicate.

## Controls and execution boundary

`python3 -B gradle/verify-world-fixture.py` runs Minecraft-free source and in-memory synthetic
controls for missing, duplicate, extra and wrong-profile/engine-filter cases, frozen complete test bodies,
retained historical descriptor, owning-mod mounting and runtime/sources archive leaks. It does
not invoke Gradle, initialize Minecraft or claim actual FML behavior.

Under an explicitly admitted source gate, `verifyFast` also compiles both fixture profiles,
checks their actual processed-resource descriptor exclusion and inspects the actual final
reobfuscated runtime JAR **and** actual sources JAR. Both must exclude all nonshipping fixture
classes/sources, inventories and world-only resources while retaining the production owning mod.

During each actual world engine startup the subscriber requires the production class, subscriber
and both world case classes plus both paid catalogue adapter/account classes to inhabit the same
named owning module. It also requires exactly
one owning ModInfo in the real `ModList` file descriptor and rejects a loaded historical world
mod. One fixed fixture-only INFO records this check; it is not a production feature record.
Each actual selected profile must complete exactly its original one case, with both latest/debug
logs present and no ERROR/FATAL or failed-decode diagnostics. Manual failed-operation/WARN review
is still required; counts and module checks do not establish full-pack, production-JAR, client,
visual, inventory or crash-durability acceptance.
